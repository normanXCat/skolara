## 📦 Settings utility — `lib/settings.ts`

```typescript
// Get all settings as a key-value object
export async function getSettings(): Promise<Record<string, string>>

// Get a single setting
export async function getSetting(key: string): Promise<string>

// Update multiple settings at once
export async function updateSettings(data: Record<string, string>): Promise<void>
```

- `getSettings()` est mis en cache avec `unstable_cache` (Next.js) ou équivalent
- Le cache est invalidé après chaque `updateSettings()`
- Utilisé côté serveur dans les Server Components (footer, contact, legal pages)

## 📦 A. Site Settings — `/admin/settings`

### API Routes
GET  /api/admin/settings        → all settings as key-value object
PUT  /api/admin/settings        → update all settings (upsert)

#### `GET /api/admin/settings`
```typescript
{
  success: true,
  data: {
    schoolName: string,
    phone: string,
    email: string,
    address: string,
    city: string,
    googleMapsUrl: string,
    facebookUrl: string,
    instagramUrl: string,
    twitterUrl: string,
    linkedinUrl: string,
    mentionsLegales: string,   // HTML
    cgu: string                // HTML
  }
}
```

#### `PUT /api/admin/settings` — Body
Même structure que la réponse GET.
- Upsert chaque clé via `updateSettings()`
- Invalide le cache après sauvegarde
- Vérifie le rôle `ADMIN`

#### Zod schema — `lib/validations/settings.ts`
- `updateSettingsSchema`
- URLs : `.url()` ou vide (`z.string().url().or(z.literal(''))`)
- Email : format valide ou vide
- Phone : string, pas de format strict
- Messages en français

**Layout** : page avec sections séparées par des cards

## 📦 B. Footer Update

**Analyse le footer existant** avant toute modification — ne change pas son design, uniquement ses données.

Remplace toutes les données hardcodées du footer par des données dynamiques depuis `getSettings()` :

- Numéro de téléphone
- Email de contact
- Adresse / ville
- Liens réseaux sociaux (affiche uniquement ceux dont l'URL est renseignée — si vide, masque l'icône)
- Lien "Mentions légales" → `/legal/mentions-legales`
- Lien "CGU" → `/legal/cgu`
- Lien "FAQ" → `/legal/faq`

Le footer est un **Server Component** — utilise `getSettings()` directement, pas de fetch côté client.

**Règle** : si une valeur est vide dans les settings, masque l'élément correspondant dans le footer proprement (pas de lien vide, pas d'icône sans URL).
